# 2026-07-29 v008 MOSS 提升 + 集成探针

## 目标
超越榜首 0.15023。v007 线上 0.16593，差 1.57 点。

## 探针结果

### 1. MOSS prompt 调参（细切段/强调不漏判说话人）— 证伪
- 细切段 prompt：016/047/030/091/001 段数几乎不变，tcpWER 49.94% vs 49.81%（+0.13）。
- 强调不漏判说话人 prompt：5/6 段 0 输出（破坏 parse 格式）。
- **MOSS 不受 prompt 控制段粒度/说话人数**，prompt 调参危险（改 prompt 破坏输出格式）。

### 2. MOSS+CAM++ per-reco 互补性 — 强
- MOSS 赢 67 段（均赢 0.20）/ CAM++ 赢 37 段（均赢 0.10）/ 平 2
- **择优上界 15.05%**（2926/19447）——**低于榜首 15.02% 几乎持平**！
- ins 531 / del 1304 / sub 1091（三项都比 MOSS 单独 818/1620/1138 降）
- 但这是 dev ref 引导，test 无 ref 难择优。

### 3. MOSS 文本 + CAM++ 说话人混合 — 证伪
- apply_diar CAM++ 说话人 → MOSS 文本 = 27.79%（比 MOSS 单独 18.39% 差 9.4 点）
- CAM++ 说话人比 MOSS 自己的差（missed 63 vs MOSS 52），覆盖反而拉差。
- **MOSS 端到端说话人已比 CAM++ 好**，不该用 CAM++ 覆盖。

### 4. MOSS del=1620 根因 — 少判说话人
- del 高的段（069/071/072/016/047）都是 MOSS 少判 1-2 个说话人（016: 2人 vs ref 3人；069: 5 vs 6）。
- missed_spk=1-2，少判的说话人所有段变 del。
- 和 CAM++/DiariZen/Sortformer 同病（EEND/LLM 都少判），MOSS 少判更少（52 vs CAM++ 63）。
- max_new_tokens 非截断（016 输出完整到 39.98s）。

## 方向裁定

- **prompt 调参封死**（破坏格式 + 不控制粒度）。
- **MOSS+CAM++ 说话人覆盖封死**（CAM++ 说话人比 MOSS 差）。
- **择优上界 15.05% 是真空间**，但 test 无 ref 难择优。
- **test 启发式候选**：CAM++ 判 >6 人 → 用 MOSS（8 段全 MOSS 赢）。但只 8 段，增益有限。
- **MOSS Pro**（cpCER 14.02 vs 0.9B 15.83）无 API，阻塞。
- **剩余最有希望**：test 启发式集成（CAM++ 多估段用 MOSS）+ 微调 prompt（不破坏格式版）。
- 主线维持 v007=18.39% dev / 16.59% 线上，距榜首 15.02% 差 1.57 点。
