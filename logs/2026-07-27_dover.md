## 详细记录

### v005 — DOVER-Lap 集成 CAM++ + Sortformer

- **思路**：per-reco 互补性强（Sortformer 赢 42 段 / CAM++ 赢 37 段 / 平 27），deep-research finding 4 冠军都是集成。用 DOVER-Lap（label mapping + voting）合并两套 diar。
- **实现**：写 `src/diarize_dover.py`，读多套 diar.json → 转 Turn → `DOVERLap.combine_turns_list` → 转回 schema。修 2 个 bug（session_id stem 后缀 / combine 返回 List[Turn] 非 List[List]）。加 `--weights` 支持自定义权重。
- **结果**：
  - rank weight（默认）：27.63% = CAM++ 默认完全一致（106 段全同），Sortformer 零贡献。
  - 等权 0.5/0.5：28.98%，falarm=2，变成 Sortformer 主导。
  - 两端都比 v002 差，DOVER voting 不工作。
- **根因**：DOVER-Lap 的 label voting 假设各系统说话人 ID 能对齐，但 CAM++（粗 2 段）和 Sortformer（细 3 段）分割粒度不同，voting 时只能选一套标签，不能真正"取长补短"。rank weight 偏 falarm 少的系统 → CAM++ 主导；等权偏向 Sortformer。
- **关键诊断**：按段择优上界 = **21.37%**（CAM++ 赢 64 段 / Sortformer 赢 40 段 / DOVER 赢 2 段）。证明：
  1. 集成方向有真收益（破 v002 1.42 点），但增益来自"按段择优"非 DOVER voting。
  2. DOVER-Lap 在本赛几乎不贡献（只赢 2 段），它的 voting 机制不适合粒度不同的系统。
  3. 离 16% 目标还差 5.4 点——单靠 CAM+++Sortformer 集成不够，需更强单模型（EEND-TA / pyannote community-1）+ 更多互补源。
- **结论**：discard DOVER voting 路线。保留"按段择优"思路但 test 无 ref → 需启发式（如按段时长/overlap 度/说话人数一致性选系统）。

## 方向裁定

- **DOVER voting 封死**（被单系统主导，不工作）。
- **按段择优上界 21.37% 落 insight**（集成有真收益但需 ref 引导，test 要启发式）。
- **距 16% 目标差 5.4 点**，当前 CAM+++Sortformer 两源不够，需：
  1. 更多互补源（pyannote community-1 要 HF token / EEND-TA 权重未发布）
  2. 更强单模型（v002 CAM++ 22.79% 已挖到头）
  3. 文本端改进（del=2473 是最大块，fun-asr 漏字，可能要换 ASR 或后处理）
- **主线维持 v002**（22.79%，线上 19.47%）。距 16% 差 6.8 点 dev / 3.5 点线上。
