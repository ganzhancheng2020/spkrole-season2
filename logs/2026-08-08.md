## 五、🔴 n-best 实测失败：oracle 扩了，捕获反而退了

§四 用 10 段子集测得 n-best 把 oracle 扩 1.093 点，遂写 `ac_nbest.py`（N 路声学排序）实测。

### ⚠️ 先记一次自造的假结果

首轮对比得 n-best 22.467% vs 1-best 15.510%（差 7 点），查后是**我搭子集时的竞态**：
复制基准目录时 n-best 仍在生成（27 段），两分钟后重新 glob 得 29 段，
ref 按 29 段建而预测只有 27 段 → **缺的 2 段被整段算作漏词**，虚增 357 错误。
**教训：与后台任务并行做子集评测时，session 列表必须一次性取三方交集并固定。**

### 公平对比（27 段三方交集）

| 口径 | tcpWER |
|---|---|
| MOSS 原始 | 16.2575% |
| **ac1best（v024 配方）** | **15.6592%** ⭐ |
| ac**nbest** margin=0.05 | 15.8449%（**退 0.186**）|
| ac**nbest** margin=0.15 | 15.7211%（仍退 0.062）|

**margin 越大越接近 1-best**（margin→∞ 时退化为全用 MOSS）→ n-best 在该裁判下**单调更差**。

### 机制：扩大候选集而不改进裁判，只会让选择更难

候选从 1 个增到 4 个，「至少有一个 FireRed 候选分数超过 MOSS+margin」的概率大幅上升，
而**分最高 ≠ 最准** —— FireRed 的候选全由 beam search 最大化该分数，自评偏置被 4 倍放大。

**oracle 扩了 1.093 点，实际捕获退了 0.186 点。空间变大 ≠ 拿得到。**

### 🔑 优先级纠正

HANDOFF 把「修裁判偏置」列为**第一优先级**，我先做了 n-best —— **顺序搞反了**。
正确顺序：**先换中立裁判，再上 n-best**。理由现在有实证：
n-best 的收益完全被自评偏置吃掉，裁判不修则候选越多越亏。

## 六、🔴 裁判偏置：HANDOFF 的第一优先级被实测否定

HANDOFF §4 把「修 v024 仲裁偏置（FireRed 自己当运动员又当裁判）」列为**最高优先级**。
本次实做并否定。

### 实现：MOSS 作第二裁判（teacher forcing）

MOSS 是 CausalLM，用 `prepare_inputs` 出 prompt 后把候选按 `[start][Sxx]text[end]` 格式拼接，
前向一次取该段 token 的 per-token 平均 log-prob。**冒烟即验对**：dev 001 段3
MOSS 给自己文本 −1.9944、给 FireRed 文本 −1.8392（Δ +0.155 判 FireRed 更好），ref 正是 FireRed 那句
—— **MOSS 在给自己输出打分时仍判对手更好**，说明打分不是自我吹捧。

### 145 个分歧段实测（前 25 session）

| 裁判 | FR更好组Δ | MOSS更好组Δ | 区分度 | 偏置 | **最优错误数** |
|---|---|---|---|---|---|
| 全用 MOSS（不仲裁）| — | — | — | — | 561 |
| **FireRed 单独** | +0.190 | −0.964 | 1.154 | −0.387 | **528** ⭐ |
| 两者相加 | +0.104 | −1.214 | **1.317** | −0.555 | 535 |
| MOSS 单独 | −0.086 | −0.250 | 0.164 | −0.168 | 550 |
| oracle | — | — | — | — | 490 |

### 三条结论

**① 「运动员当裁判」的担忧不成立。** FireRed 裁判的偏置是 **−0.387，方向偏向 MOSS 文本**，
不是偏袒自己 —— 因为 MOSS 文本本身更强，声学模型如实反映了这一点。

**② MOSS 当裁判几乎没有判别力**（区分度 0.164 vs FireRed 1.154；错误 550 vs 528）。
**中立 ≠ 有判别力。**

**③ 两者相加反而更差**（535 vs 528）。

### ⚠️ 方法论教训：「区分度」这个指标误导了我

两者相加的区分度 **1.317 > FireRed 单独 1.154（+14%）**，但真实决策**更差**。
**组均值分离度大 ≠ 决策更准** —— 决策取决于两个分布的重叠程度，不是均值差。
**今后评判信号必须直接用「按该信号决策后的错误数」，不能只看组均值差。**

### 当前捕获率与剩余空间

FireRed 单独：`(561−528)/(561−490) = 46.5%` 捕获率，与 §三 的 46% 一致。
按此捕获率，两侧仲裁的 0.951 点空间只能拿到 0.44 dev 点 → 线上约 0.42 点 → **约 0.1548，仍不到 0.15023**。

## 七、✅ 词级仲裁成功：v026（HANDOFF 三条待办的最后一条）

§六 否定了前两条待办后，只剩「词级仲裁」。

### 先量空间（不跑模型，纯对齐统计）

| 口径（全 dev 19447 词）| tcpWER |
|---|---|
| 全用 MOSS | 17.262% |
| **段级二选一 oracle**（v024 所在框架的上界）| **15.283%** |
| **词级 oracle**（乐观估计）| **10.536%** |
| **额外空间** | **4.746 点** |

⚠️ 词级 oracle 按「词覆盖」算、忽略顺序约束，属乐观上界，真实值更高。
但即便打对折也有约 2.4 点，**远超够榜首所需的 0.93 点** → 值得建。

### 实现：差异块枚举 + 声学打分

1. 对齐 MOSS/FireRed 两个 token 序列 → 切成 `eq` / `diff` 块
2. 取最长的 `MAX_BLOCKS` 个差异块（控制 2^k 爆炸），其余留 MOSS
3. 枚举 2^k 种混合，用**已验证有效的 FireRed 声学裁判**（区分度 1.154）逐一打分
4. 取最优；领先纯 MOSS ≥ margin 才换

**与 n-best 的关键差别**：n-best 是「换一整段候选」，候选越多越难选；
词级是「在同一段内逐块择优」，每个决策都是局部二选一，判别负担没有放大。

#### 2. 信号一：说话人标注的轮廓系数（ERes2NetV2 判官）

把两个人并成一个反而使轮廓系数升高（少而紧的簇天然得分高）—— 而这正是 MOSS 的失败模式。
**该信号系统性偏袒塌缩解，方向与目标相反。**

### 十三、❌ 合并层证伪：完美合并只值 0.031 点，不做

### 十四、🔴 v027 线上倒退 0.16123：双切分验收对重尾收益结构性失明

**线上 0.16123，比 v026 的 0.15756 倒退 +0.00367**，亦差于 v024 的 0.15903。
**dev −0.303 → 线上 +0.367，迁移率 −121%。本项目第二次线上倒退**（首次 v012 +0.0064）。
当前最佳退回 **v026 = 0.15756**。

#### 排除的假设

「拆新说话人在 test 上失控」—— **否**。新说话人分支占改写段的比例 dev 10% / test 10%，
test 仅新增 11 个说话人；触发率 dev 2.36% / test 2.84%，吻合。**不是死因。**

#### 真死因：收益全部集中在 3 个 session

| 口径 | 数值 |
|---|---|
| dev 净省 | 59 个错误 = 0.303 点 |
| 改善 / 恶化的 session | **11 个改善（省 112）/ 11 个恶化（亏 53）** |
| 收益前 1 段（068）占净收益 | **52.5%** |
| **收益前 3 段占净收益** | **130.5%** |
| **剔除 top-3 后的净收益** | **−0.093 点（负！）** |

**校准过的预测器本可提前判出这是倒退。** `online_ledger.md` 的校准结论白纸黑字写着：
> **dev 上的重尾收益不可外推**。估线上收益时应看「剔除 top-3 段后的 dev 收益」。

#### 🔴 更要命的：双切分验收给了假绿灯

v027 的 holdout24 改善 **−0.660**，是 train 的 3.3 倍，当时被当成「与过拟合形状相反」的强证据。
**实际上**：holdout24 净省 29 个错误，而 **068 单段就贡献 31 个** ——
**其余 23 段合计净亏 2 个**。所谓「holdout 大幅改善」= 一个 session。

**硬结论：train/holdout 双切分验收与 top-3 重尾折扣是两道正交的关卡，缺一不可。**
- 双切分抓的是**参数过拟合**（在 train 上调参、holdout 上失效）
- top-3 折扣抓的是**收益重尾**（收益集中在少数幸运 session，样本外不复现）
- **v027 完美通过前者、彻底死于后者。** 此前 v011 同型（前 3 段占 85%，迁移率 15%）。

### 十六、MOSS 参数清点：五条假设全否，基座侧确认耗尽

用户提出「调 MOSS 参数产出更强基座」，并要求参考论文/README。查了官方模型卡、
技术报告（arXiv:2601.01554）、GitHub README，以及**本地权重自带的配置与源码**（最权威）。

#### 官方文档口径

- 技术报告 arXiv:2601.01554，MLC-SLM 2026 第一名，0.9B / Apache-2.0 / 128k 上下文 / 支持 90 分钟
- **官方推理示例就是 `do_sample=False, max_new_tokens=2048`** —— 与我们 `moss_sat.py` 完全一致
- 唯一记录在案的可调项：`temperature`（vLLM 侧，模型默认 0.0）、**热词提示**、`max_new_tokens`
- 本地 `generation_config.json` 只声明 `bos/eos/pad` 与 `max_new_tokens: 5120`，**无温度/beam/惩罚项**

#### 五条假设，逐条实测否定

| # | 假设 | 实测 | 判定 |
|---|---|---|---|
| 1 | `max_new_tokens=2048` 造成截断（官方 config 写 5120）| dev 最长 session 估算 **769 token**，远未触顶 | ❌ 无截断 |
| 2 | MOSS 提前收尾导致 del | **MOSS 结束点之后的 ref 词数 = 0**，106/106 全覆盖 | ❌ 不存在 |
| 3 | 本地缓存两个 revision 不一致 | 两 snapshot 权重同为 1817113576 字节、config 逐字节相同，`main`→e8681d | ❌ 无版本问题 |
| 4 | **30 秒硬分块破坏跨块说话人一致性** | 见下，**带对照证伪** | ❌ 无边界效应 |
| 5 | prompt 调参 | 已两次封死（X11 v008；08-06 最小侵入追加，10 段中 5 段 0 输出）| ❌ 早已封死 |

#### 假设 4 的证伪（本轮最值得记的一条）

`processing_moss_transcribe_diarize.py:56-69` 确认是**无重叠 30 秒硬切 + 补零**：
```python
for start in range(0, audio.shape[0], n_samples):   # n_samples=480000=30s
    chunk = audio[start : start + n_samples]
    chunks.append(_pad_or_trim_audio(chunk, n_samples))
```
本赛音频均 41.9s → 每条被切成「0–30s」+「30–41.9s（含 18s 补零）」，结构上极可疑。

**可证伪预言**：跨 30s 边界的说话人应更容易被判成两个人。带对照实测：

| 边界 | 跨界说话人数 | 被判成两人 | 比例 |
|---|---|---|---|
| 15s | 185 | 40 | 21.6% |
| 20s | 196 | 45 | 23.0% |
| 25s | 188 | 41 | 21.8% |
| 28s | 172 | 37 | 21.5% |
| **30s（真实边界）** | **161** | **33** | **20.5%** |
| 32s | 143 | 27 | 18.9% |
| 35s | 131 | 27 | 20.6% |

**30s 处无任何尖峰，反而偏低。** 死因清楚：各块的 audio token 被**拼接进同一条序列**
（`audio_chunk_mapping`），LLM 跨块注意力照常，分块只是特征提取实现细节，**不构成信息屏障**。
补零也不影响 —— `_compute_audio_token_length` 用的是**实际**块长，padding 不占 token。

#### 结论：基座侧耗尽

MOSS 暴露给使用者的旋钮只有 prompt（封死）、`max_new_tokens`（无截断）、
`temperature`/`do_sample`（官方即用贪心，且模型未声明采样默认值）。
**没有一个能产出「更强的基座」。**

**唯一还剩的记录在案且已知不崩格式的杠杆 = 热词**（`hotword` preset 已存在，
但用的是手挑的全局词表「嗯, 唉, 哟, 哦, 雾霾, 戴口罩, 黄磊」，标注「未见收益」）。
**未试过的变体**：按 session 从 FireRed 的独立转写里抽词，做**逐段热词**
—— 相当于把另一个系统的先验喂给 MOSS。⚠️ 但它攻击的是与 v026 词级仲裁**同一批分歧段**，
收益大概率重叠；且 dev 重跑 30 分钟、test 约 2 小时。**期望价值低，列为待试但不优先。**

顺带确认：TTA（速度扰动）此前已实测能撬动塌缩，oracle 扩 1.203 点（三源里最好），
**缺的从来不是更强基座，是选择器** —— 而当时那 9 个选择器全是文本/结构派生的盲信号。

  「按改动类型分层的迁移率」正是校准的产物，而上述冲突点 1 恰好卡在这个未知上。

### 十八、✅ 校准（超期 8/3 后补做）：改动类型分档是假象，重尾程度才是真变量

用 5 对两端齐全的版本（dev 逐 session 误差 + 线上回执）做重分层。

| 预测器 | r | 斜率（理想=1）|
|---|---|---|
| dev **原始**收益 | **+0.302** | 0.17 |
| **剔 top-3 后 dev 净收益** | **+0.932** | **0.87** |

五对符号全部一致（含 v027 的负号）。**此前「架构级 65% / 选源规则 15% / 改文本 86–95%」
的分档，真实成因是各类改动的收益重尾程度不同**，不是类型本身有不同折算系数 ——
选源规则的收益天然集中在少数灾难段（v011 前 3 段占 85%），改文本的收益天然分散在几百段。

**新口径取代旧分档**：估线上收益 = **剔 top-3 后 dev 净收益 × 1.0～1.7**，不必先判断改动类型。

⚠️ n=5，r 单看不显著；两对比值因分母近零不稳定。采信依据是**符号五对全对 + 斜率 0.87 + 机制自洽**。

#### 这条结论直接化解了 §十七 的冲突点 1

冲突点 1 是「多源择优空间 1.846 够，但择优类迁移率仅 6.5–15% 折算后不够」。
**该冲突基于错误的分档框架，不成立。** 按新口径重算多源择优的期望：

| 环节 | 数值 |
|---|---|
| 多源 oracle（剔 top3）| **1.846 点** |
| × 历史捕获率 46% | 0.849 点 |
| × 新口径系数 1.0～1.7 | **0.85 ～ 1.44 线上点** |
| **需求（v026 0.15756 → 榜首 0.15023）** | **0.733 点** |

**即便按最保守的 1.0 系数，也够。** 剩下的唯一未知从「迁移率」变成了**捕获率**。

⚠️ 但捕获率的先例分歧极大：文本轴声学仲裁 46%，而**今天两个选源信号捕获率均为 0**。
→ 下一步该验的是**捕获率**，不是迁移率。

### 二十、✅ v028 输出层规范化：第一性原理找到的新轴，两道关卡首次同时通过

#### 起因：73% 的误差是文本，而其中一块根本不是识别失败

`/superpowers:brainstorming` 从第一性原理重看链路，发现**所有已挖的节点（②③④⑤）都条件于
①MOSS 的分割**，而**⑥输出环节从没人看过**。查 dev ref 词表后发现：

| 我们输出 | ref 中出现次数 |
|---|---|
| 哦 ×33 / 喔 | **0 / 0**（ref 一律写「噢」53 次）|
| 哎 ×13 / 诶 ×5 | **0 / 0**（ref 一律写「唉」36 次）|
| 阿拉伯数字 | **0**（ref 全用中文数字）|

**ref 里出现 0 次的字符共 39 种 103 次 = 0.530 点必错**，与识别能力无关，是**书写约定不匹配**。
对照组证伪「巧合」假设：`嗯/呃` ref 都用（288/48）、`吗/嘛/吧` 都用 —— 那些是真区分，不能动。

**顺带解释了一个悬案**：「三个互不相关的 ASR 都聚在 12.8–14% 纯文本」——共同下界的一部分
成因就是**共同的转写风格偏置**（语气词欠转写：ref 3.11% vs 我们 2.35%，缺 163 个 = 0.838 点），
不是音频听不清。

#### 设计上的唯一主观判断

只映射**语气词 / 数字 / 异体敬语**三类。`嘟/归/哄/软/谷/稻/孟/军` 等虽也满足「ref 出现 0 次」，
但它们是 **dev 特有人名地名的识别错误**，按 dev 对齐映射 = 纯拟合 dev 内容，**不会迁移**。
