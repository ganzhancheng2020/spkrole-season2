## 详细记录

**T1 — 保留 MOSS 说话人时间轴，只换文本**

- **思路**：2026-08-05 误差分解显示文本成本 12.390 点是最大块，其中 sub 1122（5.77%）为最大单项。
  归属与文本可分离：MOSS 的价值在说话人时间轴（v007 靠它把线上 0.19467→0.16593），文本是搭售。
  按 v011 已有段边界切音频逐段送 ASR，**天然单变量**（`out_recs = [dict(r) for r in recs]` 克隆，
  只覆盖 `words`，speaker/start_time/end_time 一律不动）。
  这是 X12 的镜像 —— X12 试过「用 CAM++ 说话人覆盖 MOSS 文本」，反向从没做过。
- **实现**：新增 `src/asr_retext.py`（重识别）+ `src/erase_speaker.py`（纯文本验收口径）。
  独立 `qwen_venv`（qwen-asr 依赖 transformers 4.57.6，装进 moss_venv 会把 5.14.1 **降级**、
  毁掉 v007 复现环境，dry-run 已拦截）。全 dev 106 session / 1234 段，0 段回退。
- **验收判据（事前定死）**：≤10.31% 成立（够破榜首所需 2.08 点）/ 10.31–12.39% 不足 / ≥12.39% 封死。
- **结果**：pad=0 → 14.13%，三项全劣。pad=0.25 → 15.17%，更劣。

### 截断混淆已排除

第一轮劣势曾归因于「段边界切在词中间」（活证据：001 段 ref「没有没有」被识成「没没」）。
pad=0.25 是这个假设的可证伪检验，结论是**部分成立但不是主因**：

| 指标 | pad=0 → pad=0.25 | 解读 |
|---|---|---|
| del | 1098 → **970** | 截断真实存在，量级约 **128 词** |
| ins | 313 → **589** | padding 把邻段词带进来，代价 **+276**，超过收益 |
| sub | 1337 → **1392** | **不降反升 → sub 增量不是截断造成的** |

`sub` 是决定性证据：若那 215 个多出的替换错误源于截断，padding 必须让它降 —— 它没降。
所以是 Qwen3-ASR **真的认错字**。（上一轮「1234 段×2 边界≈247 字」的量级估算凑得上数但归错了轴，
截断实际落在 del 上、量级 128。）

- **结论**：**discard，T1 封死。** 记为 X13（见 `memory/directions.md`）。

## 可达性探针：文本轴 oracle（CLAUDE.md 探针门）

X13 封死后，正要判「文本轴机制耗尽」，按探针门先跑机制无关的离线探针。
新增 `src/oracle_text.py`：**说话人与时间戳全部沿用 hyp，只把 words 换成 ref 原文**。
ref 按时间重叠归给 hyp 段（**不使用 ref 的 speaker 字段**，不泄露说话人答案）。

| 口径（全 dev，v011_pick） | tcpWER | ins | del | sub |
|---|---|---|---|---|
| 实际 | 16.979% | — | — | — |
| **文本 oracle** | **11.4156%** | 1083 | 1083 | 54 |
| **文本轴可达上限** | **5.563 点** | | | |

- **词数守恒校验通过**：19447 = ref 19447（脚本内置断言，不守恒即判探针无效）。
- **该数偏保守**：按时间重叠的分配是**一个可行解、非最优解**，真实下界只会更低 →
  文本轴真实空间**只会比 5.563 点更大**。结论方向不受影响。

### 残差指纹：ins == del == 1083，sub 仅 54

成对的 ins/del 是**纯归属错误**的签名（一个词放错说话人 → 正确处 del + 错误处 ins）。
文本完美后，剩余 11.42% 里 **97.6% 是「词认对了但归错人」**（1083 词 = 全部词的 5.57%）；
`sub` 仅 54 说明 collar 5s 足够宽松，时间偏移几乎不构成代价。

### 判决

**轴重开。** 破榜首需 2.08 点，oracle 给出 5.563 点 = **2.7 倍余量**。
死的是**机制**不是**轴**——X9/X13（换单模型）撞域墙、X8（LLM 纠错）死于**无音频上下文**。
三条死因共同排除的是「单模型替换」与「纯文本猜测」，**未排除「多系统在音频上各自出结果、
再在词级仲裁」**（ROVER / N-best 重打分）。

⚠️ **量级预警（事前记录）**：多系统仲裁的典型收益是相对 WER 降 5–15%，
对应此处约 **0.6–1.9 点**，而按架构级 65% 迁移率需吃到 oracle 的 37%（2.08 点）。
**单靠仲裁大概率不够，需要叠加。** 先记在此处，跑完再对账。

基建已就绪：`asr_retext.py` 可按任意段边界跑任意 ASR 出文本，多加系统 = 多跑一遍。

## 三轴 oracle 同基座重测 + 仲裁上界（当日第三轮）

此前各轴 oracle 散落在不同基座（15.32% = fun-asr 时代、15.05% = v007 时代），**互不可比**。

## 仲裁上界比对（`oracle_arbitrate.py`）

3 源逐段按 token 编辑距离选最接近 ref 者。ref 归段沿用 `oracle_text.py` 的 `assign()`
（导入复用，非重写），**不使用 ref 的 speaker 字段**。各源段结构一致性有内置断言。

- 全口径完美仲裁 **15.2466%**，空间 **1.732 点**；纯文本口径 10.4592%，空间 1.928 点。
- 源胜出分布：MOSS 275 段(22.3%) / Qwen3 pad=0 79 段(6.4%) / Qwen3 pad25 64 段(5.2%) /
  **平局 816 段(66.1%)**。

### 🔴 判定：仲裁 family 封死

**上界 1.732 < 所需 2.03** —— 即便仲裁器完美也差 0.30 点；按 42% 捕获率折算现实预期
0.73 dev 点 ≈ 0.47 线上点，缺口 0.85。

**事前预警对账**：本文件上一节写死的区间是「0.6–1.9 点」，实测 1.732 落在区间内。
预警机制生效，避免了投入几天后才发现量级不匹配。

**根因 = 66.1% 平局**：三系统不是错在不同地方，是**一起错在同一处**。
这是域墙在文本轴上的第二种形式（第一种是 X13 单模型替换失败）。

**含义**：文本轴剩余 5.563 − 1.732 = **3.83 点只能靠「修所有系统共同的错」的机制**
（域自适应类），任何形式的多系统组合都够不到。而域自适应在本项目已有两次线上倒退记录
（D5.3 微调，v012 0.17023 / v013 0.16872，均差于 v011 0.16379）—— 下一轮若走该方向，
必须先解释清楚为什么这次不会重蹈覆辙。
