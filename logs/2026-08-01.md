## 详细记录

**v010 — d5.1-pick-ensemble**

- **思路**：v008 测出 MOSS+CAM++ 的 oracle 按段择优上界 15.05%，但一直没有可用的**无 ref 启发式**去兑现。这版找规则。
- **方法论前提**：规则若在全 dev 上挑完又在全 dev 上报分，等于自欺。复用 `prep_finetune_data.py` 的分层切分（seed=0，按说话人数分层），**只在 train 81 段挑规则，holdout 25 段只用于验收**。
- **实现**：`src/pick_ensemble.py`。按总错误数（不是胜场数）扫 12 条候选规则——胜场数会骗人，赢的段多半赢得少、输的段输得多。

- **结果**：

| 规则 | train 81 | holdout 25 | 全 dev | dev 触发 | test 触发 |
|---|---|---|---|---|---|
| 全用 MOSS（v007） | 17.999% | 19.658% | 18.388% | 0 | 0 |
| R1  MOSS≤2人 | 17.509% | 18.277% | 17.689% | 19 (17.9%) | 104 (26.4%) |
| **R1a MOSS≤2人 且 CAM++≥3人** | **17.186%** | **18.256%** | **17.437%** | 10 (9.4%) | 35 (8.9%) |
| R2  MOSS段数≤5 | 17.556% | 19.724% ✗ | 18.064% | — | — |
| oracle（上界） | 14.633% | 15.034% | 14.727% | — | — |

- **结论**：keep。dev 18.39% → **17.44%（−0.95 点）**，holdout 独立验收 −1.40 点，ins/del/sub/missed 全降，仅 falarm +2，无回归。提交物 `baseline/submission_v010.json`（4592 条 / 394 session，格式校验通过）。

### 两条硬结论

1. **holdout 关卡救了一次**。R2 在 train 上 −0.44 点，直接采信就上线了；holdout 上 **+0.07 点** → 过拟合，丢弃。它只在 4 个训练段触发，样本太少。防过拟合切分不是形式主义。

2. **单信号启发式要看跨集触发率，不能只看分数**。R1 单条件 dev 触发 17.9%、test 触发 26.4%，分布明显漂移。dev 拆解：

   | 真实人数 | 段数 | 净错误变化 |
   |---|---|---|
   | 2（MOSS 判对） | 9 | −90（误伤） |
   | **3（MOSS 漏判）** | **8** | **+302（收益）** |
   | 4 / 5 | 2 | −76（误伤） |
   | 净 | 19 | **+136** |

   净赢全靠「漏判 3 人」那一支，47% 的触发是误伤。加「CAM++ 独立佐证 ≥3 人」后误伤被滤掉，dev/test 触发率回到 9.4%/8.9% 一致。**要求两个独立系统同时表态 = 廉价的置信度代理。**

**实测教训**：共用机上 MOSS **推理**比本地 M4 慢 6 倍（190s/40s 音频 vs 21s/28.6s 音频）。
根因是自回归每 token 的 CPU 开销被争抢放大（该机 load avg 36，他人进程各占 35% CPU），
GPU 本身健康（bf16 27.5 TFLOPS，利用率却只有 0-2%）。**但训练是 teacher-forcing 的单次整序列
前向反向，不吃这个亏** → 真要微调，GPU 只承担训练，推理与评测留本地。

另：GPU 侧 bf16 输出与本地 CPU fp32 **不逐字节一致**（时间戳漂 0.01-0.03s，个别文本不同）→
跨设备比分数必须同精度，否则分不清差异来自改动还是来自精度。

# 续挖：v011 双症状并集（同日第二轮）

## 方法论升级

上一轮已在 holdout 上比过 4 条规则，再反复试就等于把它变成第二个训练集。这轮改为
**train 81 内部 5 折嵌套 CV 选规则**（每折在其余 4 折上选最佳、在留出折打分 → 评估的是
「搜索流程本身」会不会过拟合），选定后**只上 holdout 验收**。

- 候选池：单条件 25 条（nspk / nseg / seg_max / seg_mean / top_share / turn_rate / dur比 / nseg比）
  + 两两合取 300 条 = 325 条。
- 嵌套 CV 结果：基线 17.999% → 搜索流程输出 **17.623%（−0.38 点）**，能泛化但弱。
- **5 折里 4 折都选中同一条 `turn_rate<=0.10`** → 稳定信号，不是噪声。

## turn_rate 是什么

说话人切换次数 / 首末时间跨度（次/秒）。MOSS 把两个说话人并成一个时，本该交替的段变成
同一标签，切换率随之塌陷 —— 「并人」的**直接痕迹**，且**不依赖它自称判了几个人**。

## R3 单独：train 赢、holdout 输

| 规则 | train 81 | holdout 25 | 全 dev |
|---|---|---|---|
| R1a（v010） | 17.186% | **18.256%** | 17.437% |
| R3 turn≤0.10 且 C≥3 | **16.474%** | 19.066% ✗ | 17.082% |

R3 在 train 上比 v010 好 0.71 点、holdout 上差 0.81 点。阈值扫描显示 0.10 是平滑最优
（0.08→16.87 / 0.12→16.76，非尖峰），逐折最坏值也只有 +0.18（v010 有一折亏 **+2.69**）——
各项前置检查都通过，**仍然没能在 holdout 上兑现**。

## 逐段诊断 → 发现互补，遂取并集

holdout 上 R3 相对 v010 净亏 37 个错误，几乎全来自**单独一段 091**：MOSS 判 2 人 / CAM++ 判 3 人，
错误 74→10（省 64），但 `turn_rate=0.137` 超阈值，R3 没触发。反过来 R3 多抓 8 段净省 27（063 一段省 43）。

→ **两条规则抓的是不同的段，谁也不含谁**。并集 E 本就在开跑前定的 5 条决赛名单里（train 16.770%），
不是看了 holdout 才拼出来的。

| 规则 | train 81 | holdout 25 | 全 dev | dev 触发 | test 触发 |
|---|---|---|---|---|---|
| 全用 MOSS（v007） | 17.999% | 19.658% | 18.388% | 0 | 0 |
| R1a（v010） | 17.186% | 18.256% | 17.437% | 9.4% | 8.9% |
| R3 单独 | 16.474% | 19.066% ✗ | 17.082% | 27.4% | 25.9% |
| **并集（v011）** | **16.770%** | **17.664%** | **16.979%** | **31.1%** | **31.2%** |
| oracle | 14.633% | 15.034% | 14.727% | — | — |

**并集是三切分全部胜出的唯一候选**，且 dev/test 触发率 31.1%/31.2% 几乎相同。

## v011 结果

dev **16.98%**（破 v007 **1.41 点**、破 v010 0.46 点）。ins 709 / del 1480 / sub 1113 /
missed_spk 43 / falarm_spk 7。提交物 `baseline/submission_v011.json`（4461 条 / 394 session）。

触发症状分布（dev 33 段）：只靠症状①「少判人数」4 段、**只靠症状②「切换率低」23 段**、
两者兼有 6 段 → R1a 单独会漏掉 23 段，含「真 5 人但 MOSS 判 3 人」这类症状①结构上够不着的。

## ⚠️ 统计效力的诚实交代

holdout 只有 25 段。自助重采样 5000 次：并集优于 v010 中位数 −0.47 点，
**95% 区间 [−3.06, +1.34] 含 0，未达统计显著**（69.6% 的重采样中并集更好）。
采信并集靠的是**三切分方向一致 + dev/test 触发率吻合**这两条结构性证据；
R3 单独恰恰是「train 赢 / holdout 输」的不一致形状，故弃。

# 线上回报 + 校准重分层（v011 提交后）

## 事实

**v011 线上 = 0.16379**（v007 = 0.16593）。破 **0.214 点**，而 dev 上是 1.41 点。

| 版本 | dev | 线上 | 偏移 |
|---|---|---|---|
| v002 | 22.79% | 0.19467 | −3.32 |
| v007 | 18.39% | 0.16593 | −1.80 |
| v011 | 16.98% | 0.16379 | **−0.60** |

| 跃迁 | dev 降幅 | 线上降幅 | **迁移率** | 类型 |
|---|---|---|---|---|
| v002→v007 | 4.40 | 2.874 | **65%** | 架构级换模型 |
| v007→v011 | 1.41 | 0.214 | **15%** | dev 上拟合的选择规则 |

## 诊断：不是过拟合，是 dev 收益重尾

v011 通过了所有防过拟合关卡（train/holdout 切分、嵌套 CV），而且 **test 触发率 31.2%
与 dev 31.1% 完全吻合**——规则在 test 上触发得完全正确，**只是触发后没赚到钱**。

真因是收益分布：

| dev 收益口径 | 数值 |
|---|---|
| 全 dev 收益 | −1.41 点 |
| **剔除收益前 3 段（016 +94 / 047 +74 / 030 +65）** | **−0.21 点** |
| **实际线上收益** | **−0.214 点** |

dev 净省 274 个错误中**前 3 段占 85%**。dev 的 106 段里恰好含 3 个 MOSS 灾难性失败段，
test 的 394 段没有按比例出现同等密度 → 线上结果精确落在「假设那 3 段暴击不复现」的预测值上。

**可操作规则：估线上收益时看「剔除 top-3 段后的 dev 收益」，不看全 dev 收益。**

## D5.1 轴判定：结构性耗尽（走可达性探针门）

oracle 逐段择优上界 14.727%（总空间 3.66 点）**同样高度集中**：

| 剔除收益最大的 N 段 | oracle 剩余空间 |
|---|---|
| 1 | 3.18 点 |
| 3 | 2.45 点 |
| 5 | 1.78 点 |
| **10** | **0.81 点**（前 10 段占 77.8%） |

v011 已吃掉 1.41 点，剩余 2.25 点。按 15% 迁移 → 线上仅 0.34 点 → **16.04%**，
距榜首 0.15023 **仍差 1.02 点**。

→ **即便做出完美 oracle 选择器，D5.1 也够不到榜首。** 未试的时间轴级分歧度 / 第三源
即便成功也被这个上界卡死，不值得再投入。落 `wiki/insights/dev-online-transfer.md`。

## 方向裁定（校准后）

- **D5.1 收官于 v011**（线上 0.16379，当前最佳），**不再主攻**。
- **主攻改为 D5.3 微调 MOSS 0.9B**。依据：闭合线上 1.36 点差距，按架构级 65% 迁移率
  倒推需约 **2.1 点 dev 级改进**；选择/后处理类只有 15% 迁移率，量级上够不着。
  微调直击已定位病根（少判说话人的 domain mismatch），基础设施已就绪。
