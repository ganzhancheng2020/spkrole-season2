
## ✅ 补上验证集监控 + 早停取 best（用户批评后引入）

**批评成立**：此前所有微调实验都是「固定轮数训完 → 跑下游 tcpWER」，
**每次评估 10+ 分钟推理、信号只有一个终点数、看不见 loss 拐点**。
项目从未建过验证集（`sim_jsonl/holdout.jsonl` 是空文件）。

### 做法

新增 `src/finetune_v2.py`：`eval_strategy=steps` + `EarlyStoppingCallback(patience)` +
`load_best_model_at_end`（按 `eval_loss` 取最优步，不取最后一步）+
`save_only_model=True`（checkpoint 从 ~5.5G 降到 ~1.8G —— AdamW 此前正因此撑爆磁盘崩过一次）。

**干净验证集**：`--source-split holdout` 生成 100 段（素材全部来自 holdout-24），
与 train-82 训练集**说话人零重叠**。

### 结果：拐点在 step 200，并推翻了旧的「2 epoch 最优」

配置 = AdamW + lr 3e-5 + train-82：

| step | eval_loss |
|---|---|
| 50 | 0.3551 |
| 100 | 0.2445 |
| 150 | 0.2259 |
| **200** | **0.2188** ← 拐点 |
| 250 | 0.2256 ↑ |
| 300 | 0.2259 ↑ |
| 350 | 0.2219 ↑ → 早停触发 |

800 条 / 有效 batch 4 → **200 步 = 恰好 1 epoch**。

🔴 **与此前用 tcpWER 试出的「2 epoch 最优」冲突**（1ep 14.9784 / 2ep 14.7280 / 3ep 14.8190）。
但那次是在 **adafactor + lr 1e-5** 下做的，本次是 **AdamW + lr 3e-5** ——
**LR 高 3 倍，达到最优所需步数自然更少。**

→ **最优步数不是常数，它随 LR 变化。** 我此前把某个配置下的局部结论当成了普适规律，
而这正是「没有验证集、只能靠昂贵下游指标去猜」的直接后果。

### 顺带确认了 AdamW 欠拟合的诊断

AdamW + lr 1e-5 的训练 loss 末段 **0.2656**（adafactor 同配置 0.1906）→ 欠拟合。
把 LR 提到 3e-5 后，验证 loss 在 200 步即触底回升 → 该 LR 下已吃透数据。**方向判对。**

### 🔴 但 best-by-val-loss 在下游崩了：19.4628%（基线 14.2499%）

拿 step200 的 best 权重跑 holdout 全链路：

| 配置 | tcpWER | ins | **del** | sub | missed_spk |
|---|---|---|---|---|---|
| AdamW lr=1e-5（固定 2 epoch）| **14.2499%** | 152 | **282** | 192 | 8 |
| AdamW lr=3e-5（早停取 best）| **19.4628%** | 184 | **496** | 175 | 6 |

**deletions 暴涨 76%（282→496）**，而 sub 略降、missed_speaker 反而更好（6 vs 8）。
输出结构也全部正常（段数 12.0 / 段长 2.03s / 人数 3.67，比 v031 更接近真值），
**只有词数掉了**（170 vs 178，真值 183）。

→ **模型没崩，是「少说话」—— 漏字。**

### 教训：val loss 最优 ≠ tcpWER 最优（exposure bias）

`eval_loss` 是 **teacher forcing** 下的 token 交叉熵：训练时永远有正确前文喂入，
**它对「自回归生成时会不会提前收尾」几乎不敏感**。
lr=3e-5 训到 val loss 最低的那个点，恰好是模型**倾向于早停生成**的状态 ——
teacher forcing 下指标漂亮，真跑起来漏字多 76%。

**正确用法（已修正）**：

- val loss 用于判断**训练动力学**：欠拟合/过拟合、LR 量级是否合理、有没有跑飞
- **最终选点不能只看 val loss**，必须用下游指标，或用能反映生成行为的代理
  （如在验证集上做真实生成后算 token 数比 / tcpWER）

⚠️ 本次实验同时改了两个变量（LR 1e-5→3e-5、固定轮数→早停取best），
**无法区分崩坏来自高 LR 还是来自 best-by-val-loss 的选点**。下一步单变量拆开。
