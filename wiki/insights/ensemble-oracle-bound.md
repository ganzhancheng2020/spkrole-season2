# 集成上界：源换了，上界跟着走（21.37% → 15.05% → 12.40%）

> 本页记三次测算。**当前有效上界 = 12.40%（微调 ck84 + 基座 v007 + CAM++，2026-08-01）**；
> 下方 15.05% 一节是 MOSS+CAM 两源时代，21.37% 是 CAM+++Sortformer 时代。结论（voting 失效 / 增益来自择优）仍成立。

## 当前上界：三源（微调+基座+CAM）= 12.40%（2026-08-01，全量 106 段）

| 系统 | dev tcpWER |
|---|---|
| 基座 MOSS v007 单独 | 18.39% |
| 微调 ck84 单独 | 16.78% |
| CAM++ 最优 v002 | 22.79% |
| 两源择优（MOSS+CAM）| 15.05% |
| **三源择优（+微调）**| **12.40%** |

- 微调 ck84 独家赢（比两源都好）**73 段**——微调修正了少判说话人（016: 2→3人），在同模型变体间产生新互补。
- **12.40% 远低于榜首 15.02%** → 即便 50% 迁移（~13.7%）也能超榜首。
- **兑现需要无 ref 启发式**：微调 vs 基座的区分信号弱（段数比/说话人数都重叠），v011 双症状在微调上误触发（15 段换差）。需为微调 ck84 专门调规则（train 81 / holdout 25 防过拟合）。
- 微调 ck84 dev 单独 16.78% 比 v011 16.98% 好，但 test 迁移差（v013 线上 0.16872 倒退）——微调在 dev 过拟合，择优规则需 holdout 验收。

## 上一代上界：MOSS + CAM++ = 15.05%（2026-07-29，v008，全量 106 段）

| 系统 | dev tcpWER | ins | del | sub | missed/falarm |
|---|---|---|---|---|---|
| MOSS 0.9B 单独（v007 主线） | 18.39% | 818 | 1620 | 1138 | 52/4 |
| CAM++ 最优（v002） | 22.79% | 1430 | 2473 | 1155 | 61/9 |
| **按段择优上界** | **15.05%** | **531** | **1304** | **1091** | — |

- 互补性：**MOSS 赢 67 段 / CAM++ 赢 37 段 / 平 2**。
- ins/del/sub **三项都低于 MOSS 单独**——不是某一项的局部改善，是整体下移。
- **15.05% 几乎持平新榜首 15.02%** → 当前图内唯一够得到目标的轴。

### 关键约束（别高兴太早）

- 15.05% 是 **dev ref 引导**的上界：每段回头看谁 tcpWER 低就选谁。test 无 ref，**不可照搬**。
- 兑现它需要**无 ref 的启发式**（按说话人数一致性 / 段时长分布 / 模型置信度选系统）。
- 已知启发式线索：CAM++ 判 >6 人的段 → 全部是 MOSS 赢（8 段）。但只 8 段，覆盖太窄。
- 历史教训：上一代择优上界 21.37%，**从未有启发式版本兑现过**。上界 ≠ 可达。

### 为什么这次的上界比上一代低这么多

上一代两源都是 diarization（CAM++ / Sortformer），文本同源于 fun-asr → 集成只能改善说话人，改不动文本 del。
这次 MOSS 是端到端 SAT，**文本和说话人一起换**，两源错误结构不同 → 择优空间大得多（del 从 1620/2473 降到 1304）。

**推论（可用于选下一个源）**：再加源时优先加**错误结构不同**的源（换范式 / 换模态），而不是同范式的另一个模型。

# 历史测算：集成上界 21.37% & DOVER voting 失效（2026-07-27）

## 结论

**按段择优上界 = 21.37%**（CAM++ 赢 64 段 / Sortformer 赢 40 段 / DOVER 赢 2 段）。
- 破 v002(22.79%) 1.42 点 → 集成方向有真收益。
- 但离 16% 目标还差 5.4 点 → CAM+++Sortformer 两源不够。
- **DOVER-Lap voting 几乎不贡献**（只赢 2 段），被单系统主导。

## 证据（v005 实测，全量 106 段）

| 配置 | tcpWER | missed/falarm | 现象 |
|---|---|---|---|
| v002 CAM++ 最优 | 22.79% | 61/9 | 主线 |
| CAM++ 默认 | 27.63% | 64/43 | falarm 多 |
| Sortformer v2 | 29.70% | 87/2 | missed 多（保守少判）|
| DOVER rank-weight | 27.63% | 64/43 | =CAM++默认完全一致，Sortformer 零贡献 |
| DOVER 等权 0.5/0.5 | 28.98% | 89/2 | =Sortformer 主导 |
| **按段择优上界** | **21.37%** | — | CAM++64/SF40/DV2 |

## 含义

### DOVER voting 失效根因
- DOVER-Lap label voting 假设各系统说话人 ID 能对齐，但 CAM++（粗 2 段）和 Sortformer（细 3 段）**分割粒度不同**，voting 时只能选一套标签，不能真正取长补短。
- rank weight 偏 falarm 少的系统 → CAM++ 主导（27.63%）；等权偏向 Sortformer（28.98%）。两端都比 v002 差。
- **DOVER-Lap 在本赛不工作**，不是调参问题，是机制不匹配。

### 集成增益来源
- 增益来自"按段择优"（ref 引导选 tcpWER 低的系统），不是 voting。
- test 无 ref → 要启发式择优（按段时长/overlap 度/说话人数一致性选系统）。
- 21.37% 是 dev 上界，test 启发式版必低于此。

### 距 16% 目标的差距
- 当前 v002=22.79% dev / 19.47% 线上。
- 集成上界 21.37% dev → 即便完美集成也只到 21.37%，离 16% 还差 5.4 点。
- **要破 16% 必须三路并进**：
  1. 更多互补源（pyannote community-1 / EEND-TA，当前都阻塞）
  2. 更强单模型（CAM++ 已挖到头，需换范式但 EEND 系全在多人段少判说话人）
  3. **文本端改进**（del=2473 是最大块，fun-asr 漏字 13%，纯文本 tcpWER=12.89% 是新下界——换 ASR 或文本后处理可能比换 diar 更有空间）

## 下一步

- **DOVER voting 封死**，不再调。
- **按段择优**留作 test 启发式版候选（但增益有限，1.42 点不够）。
- **转文本端**：del=2473 占 errors 49%，是最大块。fun-asr 漏字是主因（hyp 比 ref 少 1583s 语音）。换 ASR（paraformer 本地？）或文本后处理（段合并/补字）可能比继续调 diar 更有空间。
- **主线维持 v002**，距 16% 差 6.8 点 dev，单 diar 路线不够，需文本端协同。
