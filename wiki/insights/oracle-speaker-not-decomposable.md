# 归属 oracle 不可分解 —— 两个子集单独改都更差，只有全改才有收益

> 🔴 **本页结论已作废（2026-08-24）**：所谓「不可分解」是**命名空间混用**造成的测量假象 ——
> 改过的段贴 ref ID、未改的留 hyp ID，tcpWER 全局最优映射时 ref-A 平凡自映射抢走 hyp-1 的位置。
> 在同一命名空间内做同样的部分改写是**单调**的（只改纯段 −1.80 点）。
> 见 [[namespace-artifact-reopens-attribution]]。本页保留作为**错误口径的实证**。

## 数（106 段干净 CV 集，出货配置成品阶段）

| 口径 | tcpWER | vs 基线 |
|---|---|---|
| v040 等价链路 | **15.75%** | — |
| 只把**纯段**标签改对 | 16.11% | **+0.36 🔴** |
| 只把**混合段**标签改对 | 19.28% | **+3.53 🔴🔴** |
| **两者都改（= 全归属 oracle）** | **12.20%** | **−3.55 ✅** |

**两个子集单独做都更差，合起来才有 3.55 点。**

## 含义：这个"上界"不是可分摊的预算

tcpWER 对说话人做**全局最优映射**。`oracle_speaker` 把每段贴上它自己重叠最多的
ref 说话人，效果等同于**把整场的说话人身份换成 ref 的那一套** —— 它衡量的是
「整个划分正确」的价值，**不是「逐段改对能赚多少」的加总**。

部分改写会造出一个**半新半旧的混合划分**，全局映射下比原来更糟。

→ **归属轴的 3.55 点是一个聚类问题（整场划分），不是逐段决策问题。**
而盲重聚类已封死（2026-08-08：给 oracle k 仍得 29.804%）。

## 这一条作废了此前所有「按 oracle 上界 × 捕获率」的外推

我此前反复用「oracle 空间 × 历史捕获率 = 预期收益」估算方向价值
（[[capture-rate-scales-with-headroom]] 已经警告过一次外推翻车）。
本页给出更根本的问题：**在归属轴上，那个空间根本不能按段分摊**，
所以任何「捕获 x% 的 oracle」的说法都是无意义的 —— 捕获 50% 可能是负的。

**新判据：报一条轴的 oracle 空间时，必须同时报「部分实现是否单调」。
不单调的轴，oracle 只能当存在性证明，不能当预算。**

## 与 [[relabel-family-worth-031]] 的关系

那一页测的是 raw MOSS 阶段（纯段改对值 0.31 点）；本页测的是**成品阶段**，
纯段改对是 **−0.36 点**。两页方向一致、本页更严：
**「按段重贴标签」在出货链路上是负资产，不是小收益。**

四个机制的失败（`spk_relabel` 3.7% 捕获、声学改标签 +0.315、
