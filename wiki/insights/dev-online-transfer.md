# dev→线上迁移率：改动类型决定折算系数（2026-08-01）

## 结论

**dev 降幅不能直接当线上降幅用。折算系数取决于改动类型：**

| 改动类型 | 迁移率 | 证据 |
|---|---|---|
| **改文本内容（声学仲裁）** | **86–95%** | v020→v024：dev −0.473 → 线上 −0.449（95%）；v024→v026：dev −0.170 → 线上 −0.147（**86.5%**）|
| **架构级换模型** | **≈65%** | v002→v007：dev −4.40 → 线上 −2.874 |
| **dev 上拟合的选择/后处理规则** | **≈15%**（后续衰减到 6.5%）| v007→v011：dev −1.41 → 线上 −0.214 |

### 🔴🔴 2026-08-09 校准重分层：改动类型分档基本是假象，真正的变量是重尾程度

**本节取代下方「按改动类型分档」那张表的解释框架。**（那张表的数字仍是事实，但归因错了。）

用 5 对两端齐全（dev 逐 session 误差 + 线上回执）的版本做校准：

| 预测器 | 与线上收益相关系数 | 斜率（理想=1）|
|---|---|---|
| dev **原始**收益 | r = **+0.302** | 0.17 |
| **剔 top-3 后的 dev 净收益** | **r = +0.932** | **0.87** |

| 版本对 | 类型 | 剔top3 | 线上实际 | 比值 |
|---|---|---|---|---|
| v007→v011 | 选源规则 | +0.211 | +0.214 | **1.02** |
| v011→v020 | 选源规则 | −0.015 | +0.027 | 两端近零，比值无意义 |
| v020→v024 | 声学仲裁·段级 | +0.350 | +0.449 | 1.28 |
| v024→v026 | 声学仲裁·词级 | +0.087 | +0.147 | 1.68 |
| v026→v027 | 归属轴改写 | **−0.093** | **−0.367** | 符号一致 |

**五对符号全部一致。** 此前「架构级 65% / 选源规则 15% / 改文本 86–95%」的分档，
真实成因是**各类改动的收益重尾程度不同**，不是改动类型本身有不同的折算系数：
选源规则的收益天然集中在少数灾难段（v011 前 3 段占 85%），改文本的收益天然分散在几百段上。

**操作含义（取代此前的按类型折算）：**
> **估线上收益 = 剔 top-3 后的 dev 净收益 × 1.0～1.7，不必先判断改动属于哪一类。**

⚠️ **诚实的边界**：n=5，r=0.932 单看不构成统计显著；两对的比值因分母近零而不稳定。
采信依据是**五对符号全对 + 斜率 0.87 + 机制自洽**（重尾不可外推），不是单个相关系数。

### 🔴 2026-08-09 强制提交关卡（v027 倒退换来的）

**任何版本提交前必须报「剔除 top-3 session 后的 dev 净收益」；该值 ≤0 一律不提交。**

v027 dev 降 0.303 点、双切分同向、holdout 改善是 train 的 3.3 倍 —— 全绿，
**线上仍倒退 +0.00367**（迁移率 −121%）。事后拆开：净省 59 个错误里
**前 3 段占 130.5%**，剔除后是 **−0.093 点**；holdout 的 −0.660 实为 **068 单段**贡献
（其余 23 段合计净亏）。

**双切分验收与 top-3 折扣是两道正交关卡：**

| 关卡 | 抓什么 | v027 |
|---|---|---|
| train/holdout 双切分 | **参数过拟合** | ✅ 通过 |
| **top-3 重尾折扣** | **收益集中在少数幸运 session** | ❌ **−0.093，本应拦下** |

同型前例：v011（前 3 段占 85%，迁移率 15%）。**dev 只有 106 段，任何「靠几段大赢」的改动都不可外推。**

### 🔴🔴🔴 2026-08-13 关卡失效边界（v037 破榜首换来的）——**它会漏报**

**v037 线上 0.14857，破榜首 0.15023 共 0.00166**，其中归属轴 CAM 源重分配的
**独立贡献 = −0.00280**（v036/v037 仅差 29 条 speaker，归因干净）。
**而这个机制当时被重尾关卡判 FAIL，我据此把它的期望判成 ≈0。判错了。**

**失效机制：关卡量的是「dev 上收益是否集中」，但当机制只作用于一个子群体、
而 dev 里那个子群体太小时，「集中」是样本量的假象，不是机制的性质。**

| | dev | test |
|---|---|---|
| CAM 源 session 数（该机制唯一能作用的子群体）| **37** | **~128** |
| 机制实际触发 | **2 个** → 看着像「靠两段大赢」 | **77 个** → 其实高度分散 |

→ **用关卡前必须先问：这个机制能作用的子群体，在 dev 上有多少段？**
子群体 <50 段时，「剔 top3」等于剔掉 8%+ 的可作用样本，**关卡的集中度读数不可信**。

### ✅ 更可靠的正向信号：**反向损失 = 0**

四个数据点一致，且比重尾关卡准：

| 版本 | 反向损失（变差的 session 数）| 重尾关卡 | 线上 |
|---|---|---|---|
| **v028** | **0**（构造保证）| PASS | ✅ 迁移率 107% |
| **v035/v037 的归属轴** | **0 / 106 段** | ❌ **FAIL（漏报）** | ✅ **−0.00280，本项目最大单机制增益** |
| v027 | 多段变差 | ❌ FAIL | 🔴 −121% |
| v011 | 有变差段 | ❌ FAIL | 🔴 迁移率仅 15% |

**规则修正**：
- **反向损失 = 0 → 下行有界，可以下注**，即使重尾关卡 FAIL（但要先确认子群体够大或改动足够保守）。
- 重尾关卡仍用于**拦截**「有变差段 + 收益靠几段」的组合（v027/v011 型），**不再用于否决反向损失为 0 的改动**。

### 🔴 2026-08-13 第二条修正：**在验收集上择优 = 用掉它的预测力**

v036（基座插值）Δholdout-24 = **−0.546 点**、P(更优)=81.7%，是当日最强候选，
**线上却 +0.041 点（倍率 −0.08x，方向反了）** —— 本项目第一个方向判断失败的对。

死因与 v032 同：**0.25 这个插值比例是在 holdout-24 上压过其它 soup 变体才被选中的**。
按「配置是否在 holdout 上择优」重新分组全部干净对：

| 口径 | 对 | 方向一致 |
|---|---|---|
| **未在 holdout 择优** | v028→v031、v031→v033 | **2/2 全对** |
| **已在 holdout 择优** | v031→v034、v031→v036 | **1/2，等于抛硬币** |

→ **holdout-24 只在「不拿它选型」时有预测力。** 一旦用它比较过多个配置并挑了最好的那个，
它给出的 Δ 就主要是选型噪声，不能再当验收证据。

### 归属轴迁移率：首次实测 = 负

| 改动类型 | 迁移率 | 证据 |
|---|---|---|
| **归属轴（改 speaker 标签）** | **−121%** | v026→v027：dev −0.303 → 线上 **+0.367** |

⚠️ 该数据点来自一个重尾收益版本，**不代表归属轴本身不可用**，
只说明「重尾收益 + 未过折扣关卡」必然翻车。轴的真实迁移率仍未知。

### 2026-08-08 新增档位：改文本内容 ≈ 全额兑现

v024 与 v026 是**两次独立测量**，都落在 86–95%，比架构级还高。机制上说得通：
声学仲裁改的是**每一段的文字本身**，赚到的钱分散在几百段上（v026 dev 换 370 段 / test 换 1281 段），
**不依赖少数几段的重尾收益** —— 正是下节「为什么是 15%」里选择规则失效的那个原因的反面。

**操作含义**：给「改文本内容」类改动折算时按 **0.9** 估，别再套 0.65；
给「选哪个源」类规则折算时按 **0.1** 估，别套 0.15（该档已实测衰减到 6.5%）。

dev→线上偏移同时在系统性收窄：−3.32（v002）→ −1.80（v007）→ −0.60（v011）。
排序未反转（dev 降线上仍跟降），但**降幅严重缩水**。

## 为什么是 15%——重尾收益不可外推

这不是过拟合。v011 通过了所有防过拟合关卡：train 81 挑规则 / holdout 25 验收、
嵌套 CV、dev 与 test 触发率吻合（31.1% vs 31.2%）。**规则在 test 上触发得完全正确，
只是触发后没赚到钱。**

真因是 **dev 收益高度重尾 + dev 样本太小**：

| dev 收益口径 | 数值 |
|---|---|
| 全 dev 收益 | −1.41 点 |
| **剔除收益前 3 段（016 +94 / 047 +74 / 030 +65）** | **−0.21 点** |
| **实际线上收益** | **−0.214 点** |

v011 在 dev 净省 274 个错误，**前 3 段占 85%**。dev 的 106 段里恰好含 3 个 MOSS
灾难性失败段，test 的 394 段没有按比例出现同等密度 —— 于是线上结果精确落在
「假设那 3 段暴击不复现」的预测值上。

## 可操作规则

1. **估线上收益时看「剔除 top-3 段后的 dev 收益」**，不看全 dev 收益。两者差距越大，
   说明该改动越依赖少数幸运段，越不可外推。
2. **选择/后处理类改动按 15% 折算，架构级改动按 65% 折算。**
3. 一个改动若在 dev 上收益集中度很高（前 3 段 >50%），即便过了 holdout，
   线上预期也应打到接近「剔除重尾后」的水平。

## 对 D5.1（按段择优）轴的判定

oracle 逐段择优上界 14.727%（总空间 3.66 点）**同样高度集中**：

| 剔除收益最大的 N 段 | oracle 剩余空间 |
|---|---|
| 1 | 3.18 点 |
| 3 | 2.45 点 |
| 5 | 1.78 点 |
| **10** | **0.81 点**（前 10 段占 77.8%） |

v011 已吃掉 1.41 点，剩余 2.25 点。按 15% 迁移 → 线上仅约 0.34 点 → **16.04%**，
距榜首 0.15023 仍差 **1.02 点**。

→ **即便做出完美 oracle 选择器，D5.1 也够不到榜首。该轴对目标而言结构性耗尽。**

这道判定用的正是 AGENTS.md 的「可达性探针门」：oracle 探针不仅给出上界，
还通过收益集中度分布证明了**该上界本身不可外推**。
