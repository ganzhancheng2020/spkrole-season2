# 词级仲裁：已捕获 69%，还剩 0.41 本地点 ≈ 线上 0.003

## 空间（106 段干净 CV 集，word_arb 阶段 / pick 前）

| 口径 | tcpWER | 捕获 |
|---|---|---|
| MOSS 原始 | 17.74% | — |
| FireRed 整段换文本 | 19.42% | （更差 1.68，见 [[text-segmentation-coupling]]）|
| word_arb 现行 `M0 / B4` | 16.94% | 0.80 / 1.34 = **60%** |
| **word_arb `M0.05 / B6`（v048）** | **16.81%** | 0.93 / 1.34 = **69%** |
| **完美段级仲裁 oracle** | **16.40%** | 100% |

**剩余 0.41 本地点。** 按实测迁移率 **0.0075 线上/本地点**（见下）＝ **线上 0.003**，
是当前距榜首缺口 0.00125 的 **2.5 倍**。

⚠️ 且这只是**段级** oracle；word_arb 是**词级**的，词级上界必然更高 → 实际空间更大。

📌 **2026-08-28 修订**：上面这个 0.41 是「**换更多/换更准**」口径的空间。
换成「**撤掉误换**」口径，同一份 CV 上的空间是 **0.5245 点**（16.8098% → 16.2853%），
比 0.41 更大，且不需要任何新文本/新模型。缺口口径也已过期：现距榜首
**0.00169**（v065=0.14354 vs 榜首 0.14185），按 0.00685 迁移率 = **所需 0.247 本地点**。
见本页下方「矛盾已解决」段与 `logs/2026-08-28.md`。

**→ 仅这条轴就够破 0.145，不必先去啃归属聚类或域自适应那些贵且不确定的方向。**

## 迁移率（首次实测）

v048：本地 −0.077 点 → 线上 **−0.00058**（0.14683 → **0.14625**）。
**0.0075 线上/本地点**，与历史「架构级 65%」估计的 0.0065 吻合。
事前预测「落点约 0.1463」，实测 0.14625 —— 量级命中。

## 参数现状（均在 106 段干净集上测，四关全过）

- `MARGIN`：0.03 −0.036 / **0.05 −0.077** / 0.07 −0.051 / 0.10 +0.026 / 0.15 +0.108
  → 平滑峰，非刀刃；与 v024 段级仲裁当年测出的 0.05 同值。
- `MAX_BLOCKS`：2 +0.021 / 4 −0.067 / **6 −0.077** / **8 −0.077（与 6 逐位相同）**
  → **6 起饱和**（段内差异块很少超过 6）。是平台不是峰尖。

**两个旋钮都已到头。** 继续拿这 0.41 点必须改**机制**，不是调参。

## 已定位的机制缺陷：打分口径

`score()` 返回**整段 token 的平均**对数概率，决策用 `best_mean − base_mean ≥ MARGIN`。
但被换掉的只是几个词块 —— 20 token 的段里换 2 个，均值最多变动 2/20。
**有效阈值随段长反比缩放：对长段过严、对短段过松。**

理论上，比较「同一段音频的两个转写谁更可能」应用**总对数概率**（似然比），
平均是通用 ASR 重打分里为比较不同长度候选引入的启发式。

⚠️ 但纯总和有反向偏置（token 越少总分越高 → 偏好更短文本）。

### 🔴 实测证否：均值口径胜出

加 `SCORE_NORM=mean|sum` 开关后在 106 段干净集上扫（`MAX_BLOCKS=6`）：

| SCORE_NORM=sum 的 MARGIN | Δ | 改善/恶化 |
|---|---|---|
| 0.0 | +0.051 | 6 / 12 |
| 0.5 | +0.010 | 13 / 15 |
| **1.0（sum 最优）** | **−0.031** | 16 / 20 |
| 2.0 | −0.021 | 17 / 29 |
| 4.0 | +0.123 | 18 / 36 |
| — | — | — |
| **mean，MARGIN 0.05（v048）** | **−0.077** | **16 / 14** |

**最优 sum 也输给 mean 0.046 点，且所有 sum 档恶化均多于改善。**
→ **总和的长度偏置（偏好更短文本）盖过了均值的稀释问题。**
我那条「似然比才是理论正确口径」的论证**是错的** —— 幸而当假设去测，没当结论去交。

## 对抗性审查（2026-08-21 第二轮）：三条自我推翻

### ① 「词级上界远低于段级」—— 错

word_arb 逐**词块**选，能产出既非纯 MOSS 也非纯 FireRed 的混合文本，
所以段级 oracle 理论上不是它的上界。实测：

| 口径 | tcpWER |
|---|---|
| 段级 oracle（整段二选一）| 16.40% |
| **词级 oracle（逐块二选一）** | **16.38%** |

**只差 0.02 点 —— 混合几乎榨不出额外的东西。天花板确实在 16.4，0.43 点的空间是真的，不是低估。**

### ② 瓶颈是**裁判**，不是候选

对 988 个可判差异块（另有 206 个两源打平，占 19.6%，换任何裁判都拿不到）：

| | |
|---|---|
| 裁判与 oracle 一致 | **64.6%** |
| 该换没换（漏） | 296 词 |
| 不该换却换（误） | 154 词 |

→ **换更好的候选（更强的 FireRed）打不到这个病灶** —— 捕获率仍停在 ~68%，
只能靠压低天花板间接得分。

✅ **矛盾已解决（2026-08-28）：裁判不保守，它换得太脏。**
原先「漏 296 > 误 154」暗示的「太保守」是**错的**——那是词级块口径。改用**段级换段口径**
在同一份 106 段干净 CV 上把 shortfall 拆开（`oracle{MOSS, 出货仲裁}`，只撤回不给新文本）：

| | |
|---|---|
| 出货仲裁 341 次换段中：严格有害 | **88（25.8%）** |
| 严格有益 | 177（51.9%） |
| 代理平局 | 76 |
| **只撤掉那 88 段有害换段** | **16.2853%（−0.5245 点）** |

**误换的代价（0.5245 点）比整页原先归给「漏换」的剩余空间（0.41 点）还大**，
所以该做**精度**不是召回——这正好解释了为什么放松 MARGIN（=提高召回）反而更差。
详见 `logs/2026-08-28.md` §词级仲裁轴重开。

⚠️ 但**四个过滤信号已全部证否**（同日）：AED 自由解码投票 32.0%、LLM-seg 38.8%、
两投票人一致 38.1%、两判官（`CTX_SEGS` 0 vs 1）互投 37.6%，随机基线 25.8%，
~~**盈亏平衡约需 50%**（毁一个有益换段 ≈ 抵掉修一个有害换段）。~~
📌 **修正：盈亏平衡是 57.7%，不是 50%** —— 有益与有害换段的**单段代价不对称**：
有益 177 段共 **+1.4552 点**（0.0082/段），有害 88 段共 **−0.5245 点**（0.0060/段），
故 break-even = 0.0082/(0.0082+0.0060) = **57.7%**。撤错一段比撤对一段亏得多，
**门槛比原记录更高**，四个信号（32~39%）的差距也更大。全部实测劣于不过滤。
四个独立信号收敛在 32~39% ⇒ 这是「**文本一致性类信号整体够不到**」，不是四次运气不好。

### ③ 用 8.3B LLM 当裁判：理论上可疑

FireRedASR2-LLM 的解码器是 **Qwen2-7B-Instruct**。而
[[arbitration-signal-must-be-acoustic]] 记着 LM 打分的经典失效模式：
「FireRedASR2 的错误是**流畅的错误**……流畅 ≠ 准确」，当年 LM 困惑度打分**方向是反的**。
**换个更强的语言模型当裁判，放大的正是这个偏置。**

## 打分口径：三种病（实测）

| 口径 | 机制 | 结果 |
|---|---|---|
| `mean` 整段平均 | 局部改动被**整段长度稀释**（20 token 换 2 个，均值最多动 2/20）| **−0.077（现行最优）** |
| `sum` 整段求和 | token 越少总分越高 → **偏好更短文本** | 最优 −0.031，输 0.046 |
| `block` 差异区求和 | 同一长度偏置，且**更烈** | **+0.848**，del 1435→**1738**，7 改善/44 恶化 |
| `blockmean` 差异区平均 | 去稀释 + 去长度偏置 | 🔴 **+1.049，比 block 还差**（5 改善 / 52 恶化）|

### 🔴 「整段稀释」这个说法本身是错的

`blockmean` 消掉了长度偏置，`del` 却仍是 **1687**（mean 为 1435），且**比 block 求和更差**。
→ **删词不是长度偏置造成的**，我的整条诊断链错了。

真正的机制是**反过来的**：**整段上下文不是稀释噪声，它是信号。**
整段打分时，一个局部看着好、但放进上下文不合理的替换，会被**下游 token 的概率拉低**而否掉。
只在差异区打分等于**把这道制约拿掉**——所以两种块级口径都换得更凶
（537 段 vs mean 的 416），也就删得更多。

### 第三次尝试：znorm（不改打分，只改阈值缩放）—— 也输

既然整段上下文是信号，就别动分子。改成信噪比判据：
**z = Δ整段总和 / √k ≥ MARGIN**（k = 变动 token 数）。
推导：每 token 的 log-prob 差方差为 σ²，k 个 token 求和后噪声 ∝ √k，
故固定阈值会「短块被轻信、长块被苛求」。

实测 m=0：**+0.262**（8 改善 / 25 恶化，自助 [+0.100, +0.443] 整体在正侧）。

**判死依据不靠外推**：m=0 时 znorm 换 **439** 段、mean 换 **416** 段 ——
**触发量相当而结果更差 ⇒ znorm 的排序质量本身劣于 mean**。
收紧阈值只能删掉最差的那些换，改变不了排序，故更大 margin 也追不上。

## 打分/阈值口径轴：五个变体全部封死

| 口径 | 成品阶段 Δ |
|---|---|
| **mean 整段平均（出货）** | **−0.077** |
| sum 整段求和 | −0.031 |
| znorm 整段和 / √k | +0.262 |
| block 差异区求和 | +0.848 |
| blockmean 差异区平均 | +1.049 |

**任何偏离「整段平均」的聚合方式都更差。**

→ **裁判 64.6% 的块级准确率是 FireRedASR2-AED 声学模型本身的性质**，
不是分数聚合方式的问题。那 0.43 点，换算分方式拿不到。

**打分口径轴封死。`mean`（整段平均）是对的，而且理由与我原先设想的相反。**

→ 推论：**裁判 64.6% 的准确率是声学模型本身的性质，不是聚合方式的问题。**
要提高它只能换声学模型，而 8.3B 的解码器是 Qwen2-7B，正撞 LM 打分「流畅≠准确」的失效模式。

## 三个旋钮均已到头

`MARGIN`（峰 0.05）· `MAX_BLOCKS`（6 起饱和）· `SCORE_NORM`（mean 胜）。
**剩余 0.41 点不是调参能拿的**，需要更准的裁判；而裁判（FireRed 声学似然）
在 v024 已被证明是所有试过的候选里最优的（换裁判、加裁判都更差）。
→ 这条轴今日到此，v048 的配方是当前最优。
